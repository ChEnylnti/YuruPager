# YuruPager 产品需求文档

- 版本：v0.5
- 产品类型：AI 编程代理远程通知、审批与监督工具
- 状态：需求草案
- 更新日期：2026-08-11

## 1. 产品概述

YuruPager 用于在手机上统一监督和管理不同电脑、服务器及办公环境中运行的 AI 编程代理。

当 Codex 请求执行敏感操作、提出问题、完成任务或发生错误时，YuruPager 将事件发送到用户手机。用户可以在手机上批准、拒绝或回答，结果随后返回对应电脑，使 Codex 继续执行。

用户可能同时拥有个人、公司和其他团队的工作环境。YuruPager 通过工作空间隔离这些环境，并通过一个账户提供统一的设备、会话、待办和通知视图。

Codex 和代码仍然运行在用户电脑或服务器上，YuruPager 不在云端运行模型，也不上传完整代码库。

产品定位：

> Your agents page you when they need a decision.

长期产品形态是一个跨设备、跨工作空间的 AI Agent Control Plane。

## 2. 产品目标

- 用户离开电脑后仍能及时处理 Codex 的权限请求。
- 减少 Codex 因等待人工确认而长时间暂停。
- 让用户通过手机查看任务状态、回答问题和接收完成通知。
- 让用户通过一个账户统一管理个人、公司和团队环境中的设备与代理会话。
- 支持多个成员在同一工作站上查看和协作处理代理会话，同时保留清晰的责任归属。
- 记录并汇总代理会话的 Token 消耗，帮助个人和团队了解使用量与成本趋势。
- 为敏感操作提供明确、可靠且可审计的人工审批机制。
- 严格隔离不同工作空间的数据、设备、策略和审计记录。
- 在不上传源代码的前提下完成远程控制。

## 3. 目标用户

- 使用 Codex CLI 的个人开发者。
- 同时运行多个 AI 编程任务的高级开发者。
- 在远程服务器或开发机上运行 Codex 的用户。
- 同时参与个人项目、公司项目和多个团队项目的开发者。
- 后续扩展到需要团队权限和审计能力的研发团队。

## 4. 核心领域模型

### 4.1 用户账户

- 一个用户使用一个全局账户登录 YuruPager。
- 一个用户可以拥有或加入多个工作空间。
- 用户注册后自动获得一个个人工作空间。
- 用户退出公司或团队工作空间后，仍可继续使用个人工作空间。

### 4.2 工作空间

工作空间用于隔离不同的身份、设备、策略和数据，类型包括：

- 个人工作空间。
- 公司工作空间。
- 其他团队工作空间。

每个工作空间独立拥有：

- 成员及成员角色。
- 设备和设备凭证。
- Codex 会话及审批请求。
- 权限策略和通知策略。
- 审批历史和审计记录。
- Token 用量记录和统计。

### 4.3 成员关系与角色

用户通过成员关系加入工作空间。MVP 定义以下基础角色：

- Owner：管理工作空间、成员、设备、策略和数据删除。
- Admin：管理设备、策略和审计记录。
- Member：使用授权设备并处理其有权处理的请求。

后续支持按设备、项目、风险等级和审批类型配置更细粒度的权限。

### 4.4 设备与会话

- 一个工作空间可以包含多个设备。
- 一个设备注册实例同一时间只能属于一个工作空间。
- 一个设备可以同时或先后运行多个 Codex 会话。
- 一个 Codex 会话可以产生多个事件和审批请求。
- 公司设备由公司工作空间拥有，不因某个成员离开而转移到其个人账户。
- 设备转移工作空间必须重新认证或重新配对，并生成新的设备凭证。
- 同一台物理电脑如果同时用于个人和公司环境，应使用相互隔离的连接器配置和设备身份。

本文将运行 Codex 并注册到 YuruPager 的电脑或服务器称为“工作站”。在数据模型中，工作站属于设备的一种，MVP 可将 `Workstation` 与 `Device` 使用同一实体表示。

### 4.5 工作站协作

- 一个工作站可以授权给工作空间中的多个成员使用。
- 工作空间成员不会因为加入工作空间而自动获得所有工作站的访问权限。
- 工作站访问权限至少区分查看会话、处理普通请求、审批高风险请求和管理工作站。
- 每个会话记录发起人；无法识别发起人时应明确标记为系统或未知来源，不得错误归属给审批人。
- 每次批准、拒绝、回答和管理操作记录实际操作者。
- 多人同时处理同一请求时，只接受第一个有效决定，其他用户立即看到请求已处理及处理人。
- 被撤销工作站权限的成员应立即失去该工作站的会话、请求和后续通知访问权。

### 4.6 Token 用量

- Token 用量归属到工作空间、工作站和代理会话。
- 在上游能够提供时，记录提供商、模型、输入 Token、缓存输入 Token、输出 Token、推理 Token 和总 Token。
- 记录数据来源和统计状态，区分上游精确值、本地计算值和估算值。
- Token 用量可关联会话发起人，但审批人不自动承担该会话的 Token 用量。
- 成本根据可配置且有版本的模型价格计算，并明确标记为估算成本，不作为提供商账单的替代品。
- Token 统计不保存提示词、回复正文、代码、Diff 或完整终端输出。

领域关系：

```text
User
  └── Membership
        └── Workspace
              ├── Device
              │     └── AgentSession
              │           ├── ApprovalRequest
              │           └── TokenUsageRecord
              ├── WorkstationAccess
              ├── Policy
              └── AuditEvent
```

## 5. MVP 支持范围

- 首期支持 Codex CLI。
- 首期支持 macOS，后续支持 Linux 和 Windows。
- 提供安装型 PWA 和原生 SwiftUI iOS 客户端；Android 当前使用 PWA。
- 支持多用户、多工作空间、多工作站和多个 Codex 会话。
- 数据模型从第一版支持工作空间和成员关系。
- MVP 提供 Owner、Admin 和 Member 基础角色，高级团队权限后续实现。
- MVP 支持工作站级成员授权和多人协作处理请求。
- MVP 记录会话级 Token 用量，并提供按工作空间、工作站和时间范围的汇总。
- MVP 支持 Web/PWA 与 iOS 向在线 Codex 会话发送受限图片，并临时显示 Codex 明确返回的图片；格式、大小、隐私和可靠性边界见 ADR-019。
- 不包含完整远程终端、代码编辑器、Diff、Git 和 PR 管理。
- 不包含任意文件附件、云端图片历史、公开图片链接或工作站离线图片队列。

## 6. 核心工作流程

1. 用户创建或选择目标工作空间。
2. 用户在电脑上运行 `npx yurupager setup`。
3. 安装程序配置 Codex 集成并启动本地连接器。
4. 手机扫描二维码，将设备安全配对到所选工作空间。
5. Codex 开始执行任务。
6. 本地连接器捕获审批、提问、完成或失败事件。
7. 需要人工决定时，Codex 暂停执行。
8. YuruPager 向有权处理该请求的用户手机发送推送通知。
9. 用户在手机上确认工作空间、设备、项目和请求上下文后批准、拒绝或回答问题。
10. 决定返回对应电脑，本地连接器将结果交给 Codex。
11. Codex 继续执行，并将结果写入所属工作空间的审计记录。
12. 连接器持续采集 Codex 提供的 Token 用量事件，服务端按会话幂等汇总。

## 7. 功能需求

### 7.1 电脑端连接器

- 一条命令完成安装和配置。
- 登录账户或通过二维码完成设备配对。
- 配对时明确选择设备所属工作空间。
- 监听 Codex 会话开始、审批、提问、完成和失败事件。
- 在 Codex 提供相关事件时采集模型信息和 Token 用量。
- 在等待审批时阻塞对应操作。
- 将手机返回的决定传递给 Codex。
- 在用户明确提交时接收经过限制和校验的图片，在工作站本地保存并作为 Codex 图片输入；服务端不得持久化图片字节或本地路径。
- 支持心跳检测、自动重连和断线恢复。
- 显示连接状态、设备名称、所属工作空间和最近事件。
- 支持卸载、重新配对和撤销设备访问。
- 设备变更工作空间时必须重新配对并轮换密钥。
- 不上传源代码、文件内容、Diff、环境变量和 API Key。

### 7.2 手机客户端

- 用户注册、登录和退出。
- 创建、加入和切换工作空间。
- 扫描二维码并将电脑配对到指定工作空间。
- 提供跨工作空间统一视图，展示所有有权访问的设备和请求。
- 支持按工作空间、设备、项目、状态和风险等级筛选。
- 查看在线和离线设备。
- 查看运行中、等待处理、已完成和失败的会话。
- 接收权限请求、问题、完成和失败通知。
- 查看请求所属工作空间、电脑、项目、会话、工具、命令和时间。
- 支持批准、拒绝、填写拒绝原因和回答问题。
- 高风险操作支持二次确认或生物识别。
- 查看通知和审批历史。
- 查看当前会话及有权限范围内的 Token 用量与估算成本。
- 查看 Codex 明确返回的图片，并选择、预览、移除和发送 PNG、JPEG 或 WebP 图片；支持图片独立消息、上传取消和失败后显式重试。
- 管理有权限的设备、推送设置和默认超时策略。
- 工作空间和设备信息必须在审批界面中持续可见，降低跨环境误操作风险。

### 7.3 工作空间与统一设备管理

- 用户可以通过一个账户管理多个工作空间。
- 系统默认创建个人工作空间。
- 用户可以创建或加入公司和团队工作空间。
- 每个工作空间独立管理成员、设备、策略和审计记录。
- 全局待办聚合用户有权处理的审批请求。
- 全局设备列表展示所有有权访问的设备及其所属工作空间和在线状态。
- 用户可以快速切换到单个工作空间视图。
- 所有请求、会话、通知和审计记录必须明确关联工作空间和设备。
- 工作空间管理员可以撤销成员或设备访问。
- 成员被移除后，其访问权限必须立即失效。
- 公司管理员不能访问用户的个人工作空间。
- 设备转移工作空间后，原工作空间中的历史审计记录不得随设备迁移。

### 7.4 工作站多人协作

- Owner 或 Admin 可以将工作站授权给一个或多个工作空间成员。
- 支持分别授予查看会话、处理普通请求、审批高风险请求和管理工作站的权限。
- 成员只能查看被授权工作站中的会话、请求和 Token 用量。
- 工作站页面展示当前运行会话、发起人、等待处理的请求以及最近活动。
- 请求详情展示发起人、当前查看者和最终处理人。
- 多个协作者可以同时查看同一会话的状态。
- 同一请求只允许一个有效处理结果，服务端使用原子状态迁移解决并发操作。
- 请求被处理后，其他协作者的页面和通知应实时更新。
- 支持将请求指派给指定成员；MVP 中指派用于责任提示，不阻止有审批权限的管理员处理紧急请求。
- 所有成员授权、撤销、指派、批准、拒绝和回答操作都写入审计记录。
- 多人协作不提供共享终端、远程代码编辑或云端持久化的完整聊天记录；已授权成员可在工作站在线时临时查看由本地 thread 重建的用户与助手文本。

### 7.5 Token 用量与成本统计

- 按代理会话记录 Token 用量，并关联工作空间、工作站、项目、提供商和模型。
- 在数据源支持时分别记录输入、缓存输入、输出、推理和总 Token。
- 支持会话进行中的增量更新和会话结束后的最终校准。
- 每个上报事件包含幂等键或单调递增序号，重连和重复上报不得重复累计。
- 展示单个会话的 Token 明细和估算成本。
- 支持按时间范围汇总工作空间、工作站、项目、模型和会话发起人的 Token 用量。
- 显示统计数据的来源、最后更新时间以及精确或估算状态。
- 模型价格表必须带生效时间和版本，历史成本使用当时生效的价格版本计算。
- 当无法获得可靠用量时显示“不可用”或“不完整”，不得以零代替缺失数据。
- 支持导出最小化的用量报表；导出内容默认不包含提示词、代码或终端输出。
- 后续支持工作空间预算、用量阈值告警和配额策略。

### 7.6 权限策略

- 支持 Ask、Allow、Deny 三种行为。
- 可以按工具类型配置策略。
- 读取文件可以设置为自动允许。
- 编辑文件、Shell、网络访问可以设置为询问。
- 删除文件、强制推送等高风险操作默认必须询问。
- 审批请求默认 5 分钟超时。
- 超时后可以选择拒绝或退回 Codex 原生审批界面。
- 无法连接服务时默认不得静默执行高风险操作。
- 策略优先级为：平台强制安全规则 > 工作空间策略 > 设备策略 > 项目策略 > 用户偏好。
- 下层策略不能绕过上层强制限制。
- 每个请求应记录最终采用的策略、策略来源和当时的策略版本。

### 7.7 通知系统

- 权限请求通知。
- Codex 提问通知。
- 任务完成通知。
- 任务失败通知。
- 电脑离线或连接恢复通知。
- 通知明确展示所属工作空间和设备。
- 点击通知直接进入对应请求。
- 请求已经被处理时，其他设备上的通知同步更新。
- 用户可以按工作空间配置通知偏好。
- 推送内容遵循最小披露原则，锁屏状态不得暴露敏感命令或项目内容。

### 7.8 服务端

- 用户、工作空间、成员关系、工作站访问、会话和设备认证。
- 电脑与手机配对。
- 接收并分发 Codex 事件。
- 管理待审批请求和请求状态。
- 使用 WebSocket 或长轮询与电脑保持连接。
- 通过 APNs、FCM 或 Web Push 发送通知。
- 接收用户决定并可靠返回电脑。
- 支持请求超时、取消、幂等和防重复处理。
- 保存最小化审计记录。
- 幂等接收、校准和聚合 Token 用量记录。
- 提供账户、工作空间、成员、设备、工作站访问、策略、用量和历史记录 API。
- 所有服务端查询和写入必须执行工作空间级授权校验。
- 支持成员撤销、设备撤销和凭证轮换立即生效。

## 8. 请求状态

- `pending`：等待用户处理。
- `approved`：用户已经批准。
- `denied`：用户已经拒绝。
- `expired`：请求已经超时。
- `cancelled`：Codex 或电脑端取消请求。
- `delivered`：决定已经成功返回电脑。

同一个请求只能产生一个最终决定，重复点击、并发审批或多个手机同时操作不得导致重复执行。所有状态迁移必须经过服务端校验，并写入结构化审计记录。

## 9. 安全与隐私

- 所有网络通信使用 HTTPS/WSS。
- 电脑和手机使用独立设备密钥。
- 不同工作空间使用独立的设备凭证和授权边界。
- 配对二维码必须短期有效且只能使用一次，并绑定目标工作空间。
- 请求包含签名、时间戳、随机数和幂等键。
- 防止请求伪造、重放和重复审批。
- 手机认证令牌保存在 Keychain 或 Keystore。
- 日志自动隐藏访问令牌、密码、环境变量和常见密钥。
- 服务端只保存审批所需的最少数据。
- 默认不保存完整终端输出和代理聊天记录。
- 高风险请求超时或服务异常时默认拒绝。
- 用户可以撤销设备、清除其有权管理的历史和删除账户。
- 工作空间之间必须进行严格的数据隔离和对象级授权校验。
- 用户不能通过修改资源 ID 访问其他工作空间的数据。
- 管理员不能因管理公司工作空间而获得用户个人工作空间的访问权限。
- 用户退出或被移出工作空间后，其会话、设备和历史访问权限立即失效。
- 工作站级访问控制必须同时应用于实时事件、通知、历史记录和 Token 用量查询。
- Token 用量记录仅保存计数及必要的归属元数据，不得借统计之名保存提示词、回复正文或代码内容。
- 工作空间、设备和成员身份变更必须写入不可抵赖的审计记录。

## 10. 非功能要求

- 正常网络下，事件到达服务端应少于 1 秒。
- 大多数手机通知应在 5 秒内到达。
- 手机决定返回电脑应少于 2 秒。
- 电脑重连后可以恢复尚未过期的请求。
- 推送丢失时，应用打开后仍能同步待处理请求。
- 服务重启不得导致已批准操作再次执行。
- 连接器重连、事件重放或服务重启不得导致 Token 用量重复累计。
- 所有关键状态变化必须记录结构化日志。
- 工作空间级授权必须覆盖所有 API、实时连接和后台任务。
- 全局视图的聚合查询不得破坏工作空间的数据隔离。
- 成员和设备撤销应在所有在线连接中快速生效。
- MVP 应具备基础监控、错误告警和数据备份。

## 11. MVP 验收标准

- 用户可在 3 分钟内完成安装和手机配对。
- Codex 请求权限时能够正确暂停。
- 手机能够收到通知并展示请求上下文。
- 用户批准后 Codex 自动继续执行。
- 用户拒绝后 Codex 不执行对应操作。
- 问题回答能够正确返回 Codex。
- 任务完成和失败能够产生通知。
- 断网、超时和重复点击不会误执行操作。
- 用户可以查看完整的审批历史。
- 服务端无法读取用户的完整代码库。
- 用户可以通过一个账户查看多个工作空间中的设备。
- 用户可以快速切换个人、公司和团队环境。
- 全局待办能够聚合用户有权处理的请求。
- 每个请求都能明确识别所属工作空间、设备和会话。
- 用户不能访问未加入工作空间中的任何数据。
- 用户离开团队后访问权限立即失效。
- 工作空间强制策略不能被设备或个人设置绕过。
- 公司管理员无法查看用户个人工作空间的数据。
- 同一请求从多台手机重复处理时只产生一次有效决定。
- 多个成员可以同时查看被授权工作站中的会话，但只能执行各自被授予的操作。
- 并发处理同一请求时只接受第一个有效决定，并向其他协作者显示处理结果和处理人。
- 撤销成员的工作站权限后，其相关页面、实时连接和通知访问立即失效。
- 每个会话能够展示 Token 用量；上游不提供可靠数据时明确显示数据不完整。
- Token 汇总可以按工作空间、工作站和时间范围查询，重复上报不会造成重复计数。
- Token 统计和导出不包含提示词、代码、Diff 或完整终端输出。
